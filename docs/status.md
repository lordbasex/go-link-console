14. **Save states across the whole catalog:** MAME saves state per part of the board (each CPU, sound and video chip, and each driver's own state), so one fix covers every game with that part. Instead of fixing what shows up in one library, measure and fix by impact: a batch mode for `savecheck` that runs every set of a folder and groups the failures by driver and chip, plus a source scan that lists, per driver and chip file, the state variables never registered for saving. Fixes then go upstream in order of how many games they cover, each with its `savecheck` table. Started 2026-10-09: `cores/mame2003-plus/tools/statescan` (the source scan, a ranking over the 5372 games) and `tools/savecheck/batch.sh` (the batch mode) exist, and their first run is in the [core patches README](../cores/mame2003-plus/README.md#across-the-catalog-toolsstatescan-and-savecheckbatchsh). Its main finding: no timer of `timer.c` is in the save state, which touches every game, so that is the next fix to measure. A folder with many more sets than the current library would make the batch numbers stronger. The device already tests each game before a room resumes, so a game that does not save whole simply starts from the beginning.
15. **FinalBurn Neo as a second core:** FBNeo (libretro) runs its own sets, close to current MAME, for CPS1/2/3, Neo Geo, Konami and many other boards, with save states that work out of the box and light enough hardware needs. It would sit next to mame2003-plus, which stays for small machines such as a Raspberry Pi. Its own catalog and set check (like `pkg/romcheck` with its game list), its controls per game, the core download, the save probe per game and which core opens each set all need deciding. Evaluate first, then build.
